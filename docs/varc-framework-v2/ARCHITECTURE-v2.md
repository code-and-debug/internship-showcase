# V.A.R.C. v2.0 架构设计

## 1. 设计原则

### 1.1 自动化优先层级

```
Level 1: 全自动（无需人工干预）
├── Git 提交触发自动保存
├── 定时自动保存
├── 代码变更检测触发
└── 上下文阈值检测

Level 2: 一键操作（单命令，无参数）
├── varc-quick-save
├── varc-fork-v2 -AutoCopy
└── varc-doctor -Fix

Level 3: 智能辅助（自动填充，人工确认）
├── 模板智能填充
├── 约束自动检测
└── 分叉提示词自动生成

Level 4: 手动精细控制
├── 完整参数支持
├── 模板自定义
└── 高级配置
```

### 1.2 摩擦消除设计

| v1.0（高摩擦） | v2.0（零摩擦） |
|---------------|---------------|
| 记忆多个参数 | 无参数，智能推断 |
| 手动填写模板 | 必填项从15+减少到3项 |
| 复制粘贴到新对话框 | 一键复制到剪贴板 |
| 定期检查状态 | 守护进程自动监控 |

## 2. 核心组件

### 2.1 智能推断引擎

```powershell
# 保存原因推断
Reason = Git commit message
      || 文件变更摘要
      || 默认时间戳

# 测试状态推断
Status = 运行验证命令的结果
      || PENDING (如果跳过验证)

# 优先级推断
Priority = Context > 80% ? critical
        : Context > 60% ? high
        : normal
```

### 2.2 自动化触发器

```yaml
auto_save:
  triggers:
    # Git 触发
    - type: git_commit
      enabled: true
      
    # 时间触发
    - type: time_interval
      enabled: true
      interval: "10m"
      
    # 文件变更触发
    - type: file_change
      enabled: true
      patterns: ["*.spec.ts", "*.test.ts"]
```

### 2.3 一键分叉流程

```
1. 自动检测当前会话
   └─> 通过 current.lnk 或最新文件

2. 提取关键信息
   ├─> session_id (作为 parent)
   ├─> 约束列表
   ├─> 代码片段
   └─> 阻塞点

3. 生成新会话
   ├─> 创建新 session_id
   ├─> 复制约束
   └─> 生成分叉提示词

4. 输出
   ├─> 保存新会话文件
   ├─> 更新 current.lnk
   └─> [可选] 复制提示词到剪贴板
```

## 3. 与 v1.0 的对比

| 方面 | v1.0 | v2.0 |
|-----|------|------|
| **保存操作** | 手动，多参数 | 自动或一键，无参数 |
| **模板填写** | 15+ 必填项 | 3 必填项 |
| **分叉操作** | 手动复制粘贴 | 一键生成+复制 |
| **健康检查** | 无 | 完整检查+自动修复 |
| **Git 集成** | 简单 commit | 自动保存钩子 |
| **IDE 集成** | 无 | VS Code 任务+配置 |
| **CI/CD** | 无 | GitHub Actions |

## 4. 技术债务与未来规划

### 4.1 当前限制

1. **上下文检测**: 目前使用估算，非真实 AI API 数据
2. **跨平台**: 主要支持 PowerShell，Bash 版本功能有限
3. **协作**: 仍为单人设计，多人协作需额外规划

### 4.2 v2.1 规划

- [ ] AI API 集成（获取真实上下文使用率）
- [ ] Web 界面（会话可视化）
- [ ] 多人协作（锁机制、合并冲突）
- [ ] 更多 IDE 插件（JetBrains、Vim）

## 5. 使用模式

### 5.1 个人开发者（推荐）

```
初始化 ──> 启动守护模式 ──> 专注开发
              │
              └──> 自动保存
              └──> 上下文耗尽时自动提醒
              └──> 一键分叉继续
```

### 5.2 团队使用

```
开发者A  ──fork──> 开发者B  ──fork──> 开发者A
   │                    │                    │
   └─ 会话链追踪 ───────┴─ 会话链追踪 ───────┘
```
