# RAC-DIVERGE：发散-验证增强协议

> 针对职业规划、重大决策等场景的 RAC 增强模块  
> 解决"AI 只会基于显性信息做线性推导"的问题

---

## 问题诊断

传统 AI 建议的通病：

| 缺陷 | 表现 | 案例 |
|-----|------|------|
| **线性推导** | 只看显性标签 | [专业] → [ obvious 岗位 ] |
| **忽视竞争** | 不提谁和你竞争 | 不提大厂 PM 岗被 985/211 卷 |
| **经验盲区** | 忽略时间窗口 | 不提对口岗位被 1-3 年经验者占据 |
| **路径遗漏** | 想不到差异化选项 | 漏掉[岗位C]、[岗位D]等 |
| **无法验证** | 建议听起来对但无法落地 | "做产品"→然后呢？ |

---

## 四维增强框架

### 一、发散维度：强制非线性探索

#### 1.1 显性路径 vs 隐性路径

AI 必须同时输出两类路径：

```markdown
**显性路径**（基于你的标签直接推导）：
- [你的专业] → [ obvious 岗位A ]
- [你的专业] → [ obvious 岗位B ]

**隐性路径**（需要跨域映射，你不一定能想到）：
- [你的专业] + [经验A] → [差异化岗位C]
- [你的专业] + [技能B] → [差异化岗位D]
- [你的专业] + [资源C] → [差异化岗位E]
- ...

要求：隐性路径数量 ≥ 显性路径数量
```

#### 1.2 反共识强制提问

AI 必须回答以下问题（打破思维定势）：

```markdown
**反共识检验**：
1. 如果大多数人都会建议你选 A，那 A 可能已经是红海，有哪些人少但正确的路？
2. 你的哪些"劣势"在特定场景下可能是优势？
   （例：非 92 学历在大厂是劣势，但在中小厂可能是"稳定预期"优势）
3. 如果 3 年后这个建议失效了，最可能的原因是什么？
```

#### 1.3 时间窗口分析

```markdown
| 路径 | 当前窗口期 | 3年后预判 | 入场建议 |
|-----|-----------|----------|---------|
| 大厂 PM | 紧缩（裁员潮）| 更卷 | 不建议正面竞争 |
| [行业]实施顾问 | 扩张（政策驱动）| 趋于饱和 | 尽快入场 |
| [行业]数据分析师 | 早期（蓝海）| 爆发增长 | 提前布局 |
```

### 二、深度维度：解剖竞争格局

#### 2.1 竞争者画像矩阵

对于每条推荐路径，必须回答：

```markdown
**路径：[目标岗位名称]**

谁和你竞争这个岗位？
| 竞争者类型 | 他们的优势 | 他们的劣势 | 你的差异化切入点 |
|-----------|-----------|-----------|----------------|
| 985/211 计算机本科 | 学历背书、技术基础 | 缺乏行业场景理解 | 强调实习经验 |
| 工作 1-3 年的转行 PM | 有产品方法论 | 行业壁垒 | 强调科班背景 |
| 工作 1-3 年行业经验者 | 深度行业知识 | 缺乏技术背景 | 技术+行业复合背景 |

结论：你的差异化在于【技术+行业场景】，避开纯技术型和纯行业型竞争
```

#### 2.2 准入壁垒拆解

```markdown
**路径：[目标岗位名称]**

硬性门槛：
- 学历：大厂卡 985/211（✗ 你不满足）
- 经验：通常要求 1-3 年（✗ 你不满足）
- 证书：NPDP/PMP（△ 可快速补齐）

软性壁垒：
- 行业认知（✓ 你有）
- 技术理解力（✓ 你有）
- 产品作品集（✗ 需构建）

结论：大厂通道被堵死，应主攻中小行业公司
```

#### 2.3 为什么是你？（差异化验证）

```markdown
必须回答：用人方为什么选你而不是别人？

错误回答："因为你很努力"
正确回答："因为你有实习经验+技术背景，比纯技术背景更懂行业场景，
          比纯行业背景更懂技术实现，是稀缺配置"
```

### 三、逻辑严谨维度：因果链验证

#### 3.1 建议→结果的因果链

```markdown
**建议**：先做[岗位A]，再转[岗位B]

因果链验证：
1. [岗位A]积累现场经验 → 
2. 理解客户真实痛点 → 
3. 能提出优化建议 → 
4. 内部转岗或跳槽[岗位B]

关键假设：
- 假设1：实施岗位确实能接触产品决策层（需验证）
- 假设2：公司有内部转岗通道（需验证）
- 假设3：实施经验被市场认可为产品经验（需验证）

风险点：如果公司在实施和产品之间有高墙，这条路径就失效了
```

#### 3.2 反事实检验

```markdown
如果以下情况发生，你的建议还成立吗？

- 假设你没有相关实习经验，这个建议还成立吗？
- 假设 3 年后行业政策收紧，这个建议还成立吗？
- 假设 AI 替代了初级工作，这个建议还成立吗？
```

#### 3.3 边界条件声明

```markdown
此建议仅在以下条件下有效：
- 你愿意接受前 2 年低薪（实施起薪低于开发）
- 你能在实施期间主动接触产品工作
- 目标公司有从[岗位A]转[岗位B]的先例

如果以上任一条件不满足，建议作废
```

---

### 四、验证维度：从建议到行动

#### 4.1 信息溯源要求

```markdown
AI 必须声明信息来源：

- 【数据】[行业]增长率 X% → 来源：[具体报告]
- 【观察】[岗位A]转[岗位B]是常见路径 → 来源：[样本观察]
- 【推测】中小行业公司更看重经验而非学历 → 置信度：中（需验证）
```

#### 4.2 72 小时落地检查

每个建议必须配套：

```markdown
**建议**：考虑[目标岗位]

72 小时内可执行的验证动作：
1. 上 Boss 直聘搜索"[目标岗位]"，记录薪资区间和要求（30分钟）
2. 找 2 个在该岗位的人做信息访谈（通过校友/LinkedIn）（2小时）
3. 查看 3 家目标公司官网，了解产品线和客户类型（30分钟）
4. 整理自己的"[核心技能]+[行业知识]"经历，看能否匹配 JD 关键词（1小时）

如果以上动作执行后你发现：
- 薪资低于预期 → 重新评估
- JD 要求你有证书 → 将考证加入计划
- 校友反馈转[目标岗位]很难 → 考虑其他路径
```

#### 4.3 证伪机制设计

```markdown
如何证明这个建议是错的？

- 如果你在 3 个月内投 50 份[岗位A]简历无面试 → 可能是简历问题或市场饱和
- 如果你面试 5 家都被问"为什么不直接做[岗位B]" → 路径设计有误
- 如果你发现[岗位A]完全接触不到[岗位B]决策 → 转岗假设不成立
```

## 一键启动模板

```markdown
【RAC-DIVERGE 模式启用】

我是[你的学校][你的专业][学历]，正在做职业规划。

请严格遵循以下协议：

**发散要求**：
1. 必须提供 ≥4 条隐性路径（非 obvious 的选择）
2. 必须分析每条路径的"时间窗口"（现在入场 vs 3年后）
3. 必须回答"如果大多数人都建议 A，那 A 的问题是什么"

**深度要求**：
1. 对每条路径，拆解"谁和你竞争"（学历/经验/背景维度）
2. 明确准入壁垒（硬门槛和软壁垒）
3. 回答"为什么选你而不是别人"，必须具体而非套话

**逻辑要求**：
1. 展示建议→结果的完整因果链
2. 标注关键假设和边界条件
3. 进行反事实检验（如果 X 不成立，建议还有效吗）

**验证要求**：
1. 区分【数据】、【观察】、【推测】，并标注置信度
2. 为每个建议提供"72小时落地检查"（具体可执行动作）
3. 设计"证伪机制"（什么情况说明建议错了）

**禁止事项**：
- 禁止只基于"你的专业标签"做线性推导
- 禁止不提竞争格局（谁在和你抢这个岗位）
- 禁止不给验证方法（只给建议不给落地检查）

确认请回复："RAC-DIVERGE 已加载"，然后开始分析。
```

## 质量检查清单

- [ ] **隐性路径占比 ≥ 50%？**（防止 obvious 建议）
- [ ] **竞争分析包含 3 类以上竞争者？**（防止低估竞争）
- [ ] **差异化理由是具体而非套话？**（"你努力"不算）
- [ ] **因果链标注了关键假设？**（防止逻辑跳跃）
- [ ] **有 72 小时可执行的验证动作？**（防止建议悬浮）
- [ ] **有明确的证伪条件？**（防止无法纠错）
