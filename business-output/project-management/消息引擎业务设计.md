# 消息引擎业务设计文档

> 智慧医疗平台消息推送系统业务架构设计

---

## 一、业务背景

### 1.1 需求背景

在智慧医疗服务平台中，消息推送是连接医院、患者、医生的关键纽带。需要一套完善的消息引擎系统，实现：
- **及时性**：检查结果、预约提醒等重要信息及时触达
- **准确性**：确保消息准确送达目标用户
- **多样性**：支持微信、短信、APP推送等多渠道
- **可追溯**：消息发送记录可查，支持统计分析

### 1.2 业务目标

| 目标 | 指标 | 说明 |
|------|------|------|
| 覆盖率 | 100% | 所有关键业务节点都有消息通知 |
| 到达率 | >99% | 消息成功送达率 |
| 及时性 | <5分钟 | 从业务发生到消息推送的延迟 |
| 准确性 | >99.9% | 消息内容准确无误 |

## 三、消息场景设计

### 3.1 场景分类

| 业务系统 | 消息类型 | 触发条件 | 优先级 | 渠道 |
|---------|---------|---------|--------|------|
| **PACS系统** | 检查预约提醒 | 预约成功 | 高 | 微信+短信 |
| **PACS系统** | 检查危急值提醒 | 检查结果异常 | 紧急 | 微信+短信+APP |
| **PACS系统** | 检查预约取消 | 预约取消/超时 | 中 | 微信 |
| **体检系统** | 体检报告通知 | 报告发布 | 高 | 微信+短信 |
| **门诊系统** | 挂号成功通知 | 挂号完成 | 高 | 微信 |
| **门诊系统** | 就诊提醒 | 就诊前30分钟 | 高 | 微信 |
| **住院系统** | 入院须知 | 入院登记 | 中 | 微信 |
| **住院系统** | 费用预警 | 余额不足 | 高 | 微信+短信 |
| **排队系统** | 叫号提醒 | 即将到号 | 高 | 微信+APP |

## 四、渠道管理

### 4.1 渠道特性对比

| 渠道 | 到达率 | 成本 | 时效性 | 适用场景 |
|------|--------|------|--------|---------|
| **微信消息** | 95%+ | 低 | 实时 | 普通通知、营销消息 |
| **短信** | 99%+ | 中 | 实时 | 重要通知、验证码 |
| **APP推送** | 90%+ | 低 | 实时 | 活跃用户触达 |
| **电话** | 100% | 高 | 实时 | 危急值、紧急通知 |

### 4.2 渠道选择策略

```
消息优先级判断:

危急值/紧急通知 ──▶ 微信 + 短信 + APP + 电话
    │
重要业务通知 ─────▶ 微信 + 短信
    │
普通业务通知 ─────▶ 微信
    │
营销/推广消息 ────▶ 微信（按用户偏好）
```

### 4.3 渠道降级机制

```
发送失败处理流程:

微信发送失败 ──▶ 尝试重发(3次)
    │
    ├─ 成功 → 结束
    │
    └─ 失败 ──▶ 降级到短信发送
                │
                ├─ 成功 → 记录降级日志
                │
                └─ 失败 ──▶ 记录失败，人工跟进
```

## 五、用户订阅管理

### 5.1 订阅维度

| 维度 | 说明 | 示例 |
|------|------|------|
| **消息类型** | 按业务类型订阅 | 检查提醒、就诊提醒、费用提醒 |
| **医院范围** | 按医院订阅 | 仅接收某医院的消息 |
| **科室范围** | 按科室订阅 | 仅接收某科室的消息 |
| **时间范围** | 按时间段订阅 | 仅在工作日接收 |
| **渠道偏好** | 按渠道订阅 | 优先微信，备用短信 |

### 5.2 订阅管理接口

```typescript
// 订阅设置接口
interface SubscriptionSetting {
  userId: string;
  hospitalId?: string;
  messageTypes: {
    type: string;
    enabled: boolean;
    channels: ('wechat' | 'sms' | 'app')[];
  }[];
  quietHours?: {
    start: string; // "22:00"
    end: string;   // "08:00"
  };
}

// 订阅/退订接口
function subscribeMessage(setting: SubscriptionSetting): Promise<void>;
function unsubscribeMessage(userId: string, type: string): Promise<void>;
```

## 七、运维保障

### 7.1 监控告警

| 监控项 | 阈值 | 告警方式 |
|--------|------|---------|
| 发送成功率 | <98% | 钉钉告警 |
| 消息积压量 | >1000 | 短信+电话 |
| 接口响应时间 | >3s | 钉钉告警 |
| 渠道异常 | 连续失败>10次 | 短信+电话 |

### 7.2 故障处理

```
故障分级:

P0级 - 消息服务完全不可用
    ├── 影响: 所有消息无法发送
    ├── 响应: 5分钟内
    └── 处理: 立即切换备用通道

P1级 - 部分渠道不可用
    ├── 影响: 某渠道发送失败
    ├── 响应: 15分钟内
    └── 处理: 自动降级，人工介入

P2级 - 性能下降
    ├── 影响: 消息延迟增加
    ├── 响应: 30分钟内
    └── 处理: 扩容或优化
```

## 八、总结

消息引擎是智慧医疗平台的核心基础设施，通过标准化的消息处理能力，实现了：

1. **全场景覆盖**：检查、门诊、住院等各业务环节消息触达
2. **多渠道触达**：微信、短信、APP等多渠道智能选择
3. **高可靠性**：多重保障机制，确保消息必达
4. **可运营性**：完善的数据统计，支持精细化运营
