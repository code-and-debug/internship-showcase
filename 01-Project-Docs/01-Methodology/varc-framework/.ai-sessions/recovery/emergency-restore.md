# 🚨 紧急恢复协议 (Emergency Recovery)

## 场景判定
如果AI出现以下情况，立即执行本协议：
- 重复已明确废弃的解决方案（如再次建议使用PEG.js）
- 修改了标记为"不可变"的约束（如引入了被禁止的依赖）
- 声称"无法找到之前的代码"但文件确实存在

## 恢复步骤

### 1. 对话重置
**操作**: 新开对话，粘贴以下内容作为第一条消息：

"""
[SYSTEM RESTORE PROTOCOL]

你是该任务的接续AI。由于上下文管理需要，我们从检查点恢复。

**继承约束**（绝对不可违反）：
1. 架构：保持React Server Components
2. 依赖：禁止>100KB新依赖
3. 当前文件状态：
   - src/components/Parser.tsx (存在，不得删除)
   - src/utils/validator.ts (存在)

**当前任务**：修复Parser嵌套注释Bug（见下方测试用例）

**历史方案已废弃**（禁止再次尝试）：
- ❌ 栈深度计数（导致无限循环）
- ❌ 正则预处理（破坏位置信息）

**验证命令**：运行 `npm test -- src/parser.spec.ts` 必须通过14个测试。
"""

### 2. 状态验证
要求AI：
1. 列出当前目录结构（确认文件存在）
2. 运行验证命令（确认基础功能）
3. 确认理解约束（重复关键约束）

### 3. 继续条件
只有通过验证检查后，才允许AI开始修复工作。
