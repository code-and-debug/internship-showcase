# RAC-CAREER：求职决策实战协议

> **求职专用** | 解决"AI 只会基于学历专业给 obvious 建议"的问题  
> 适用于：职业规划、转行决策、offer 选择、求职策略制定

---

## 核心诊断：为什么传统 AI 求职建议没用

| 问题 | 典型案例 | 后果 |
|-----|---------|------|
| **线性推导** | [专业] → [ obvious 岗位 ] | 忽视大厂岗位被 985/211 卷 |
| **经验盲区** | 不提对口岗位被 1-3 年经验者占据 | 新人直接投 = 炮灰 |
| **路径遗漏** | 漏掉[岗位A]、[岗位B]等差异化路径 | 错过差异化机会 |
| **无竞争分析** | 不提"谁在和你抢这个岗位" | 盲目投递，石沉大海 |
| **无法验证** | 建议听起来对但无法落地 | 停留在纸面，无法执行 |

---

## RAC-CAREER 四步实战框架

### Step 1：INPUT（输入解构）

不只是罗列信息，而是**识别隐性资产和隐性约束**。

#### 1.1 显性信息（你直接提供的）
```markdown
- 学校：[你的学校]
- 专业：[你的专业]
- 学历：[本科/硕士/博士]
- 经验：[实习/项目经历]
```

#### 1.2 隐性资产（容易被忽视的优势）
```markdown
必须追问挖掘：
- 是否有任何项目经历（课程设计也算）？
- 是否有跨学科能力（[学科A]+[学科B]）？
- 是否有特殊资源（校友网络、家庭背景）？
- 是否有可迁移技能（英语、写作、演讲）？
```

#### 1.3 隐性约束（容易被忽视的限制）
```markdown
必须显式声明：
- 时间约束：是否急于就业？能否接受 gap？
- 地域约束：是否限定城市？是否接受出差？
- 薪资约束：最低接受线是多少？
- 学历约束：是否考虑考研/留学缓冲？
```

#### 1.4 竞争定位初判
```markdown
基于以上信息，初步定位：
- 【正面竞争区】：可以正面硬刚的岗位（你有明确优势）
- 【差异化区】：避开红海，寻找蓝海的岗位（推荐主攻）
- 【风险区】：看起来匹配实则竞争力不足的岗位（需要策略）
- 【禁区】：当前条件下几乎不可能的岗位（直接排除）
```

---

### Step 2：DIVERGE（强制发散）

**核心规则**：显性路径 ≤ 隐性路径，必须突破 obvious 选择。

#### 2.1 路径生成矩阵

从四个维度强制生成选项：

```markdown
| 维度 | 问题 | 示例路径 |
|-----|------|---------|
| **上下游延伸** | 你目标岗位的上一环/下一环是什么？ | 想做产品？先做实施/售前 |
| **规模下探** | 大厂去不了，中小厂需要什么？ | 中小[行业]公司[目标岗位] |
| **地域套利** | 哪些城市有你这个专业的需求但竞争少？ | 二线城市体制内岗位 |
| **能力拆解** | 你的复合能力能否拆开卖？ | [背景A]→[岗位C]；[背景B]→[岗位D] |
| **时间套利** | 哪些岗位现在冷门但 3 年后爆发？ | [新兴岗位] |
| **风险对冲** | 如果主路径失败，Plan B 是什么？ | 先就业再择业 |
```

#### 2.2 反共识路径挖掘

必须回答：
```markdown
1. "如果 10 个你专业的同学都选 A，那 A 的问题是什么？"
2. "你的哪些'劣势'在特定场景下可能是优势？"
   （例：非 92 学历在大厂是劣势，在中小厂可能是"稳定"信号）
3. "如果完全抛弃专业对口，你还有哪些选项？"
```

#### 2.3 时间窗口评估

```markdown
| 路径 | 当前窗口 | 3 年后预判 | 入场建议 |
|-----|---------|-----------|---------|
| 大厂 PM | 紧缩期 | 更卷 | 不建议正面竞争 |
| [行业]实施顾问 | 扩张期 | 趋于饱和 | 尽快入场 |
| [行业]数据分析师 | 早期 | 爆发增长 | 提前布局 |
| 体制内岗位 | 稳定期 | 稳中有升 | 事业单位求稳 |
```

---

### Step 3：BATTLE（竞争格局解剖）

**核心规则**：每条路径必须回答"谁在和你竞争"和"为什么选你"。

#### 3.1 竞争者画像矩阵

```markdown
**路径：[目标岗位A]（实施/售前/运营类）**

| 竞争者类型 | 他们的优势 | 他们的劣势 | 你的差异化切入点 |
|-----------|-----------|-----------|----------------|
| 985/211 计算机本科 | 学历背书、技术基础扎实 | 缺乏行业场景理解，薪资预期高 | 强调实习经验+薪资灵活性 |
| 工作 1-3 年的转行 PM | 有产品方法论、项目经验 | 行业壁垒高，学习成本大 | 强调科班背景 |
| 工作 1-3 年行业经验者 | 深度行业知识、客户人脉 | 缺乏技术背景，理解系统困难 | 强调技术实现能力 |
| 大专 IT 培训机构出身 | 技术栈专一、起薪要求低 | 缺乏系统性思维、行业知识 | 强调本科教育+复合背景 |

**结论**：你的差异化在于【技术+行业场景理解】，避开纯技术型和纯行业型竞争
```

#### 3.2 准入壁垒拆解

```markdown
**路径：[目标岗位B]（产品/分析类）**

硬性门槛：
- 学历：大厂卡 985/211（✗ 你不满足）
- 经验：通常要求 1-3 年产品经验（✗ 你不满足）
- 证书：NPDP/PMP（△ 可 3 个月补齐）

软性壁垒：
- 行业认知（✓ 你有）
- 技术理解力（✓ 你有）
- 产品作品集（✗ 需 1-2 个月构建）
- 用户访谈能力（✗ 需训练）

结论：大厂通道被堵死，应主攻中小行业公司或先做实施/运营转岗
```

#### 3.3 差异化价值主张（UVP）

不是"你很努力"，而是具体的**不可替代性**：

```markdown
❌ 错误："因为我学习能力强，对行业感兴趣"

✅ 正确：
"我有[实习/项目]经验，知道[行业]真实工作流程和痛点，
 同时我有技术背景，能和研发团队用同一语言沟通。
 我比纯技术背景更懂客户，
 比纯行业背景更懂技术实现，是稀缺配置。"
```

### Step 4：VERIFY（验证落地）

**核心规则**：每个建议必须有"72 小时可执行动作"和"证伪机制"。

#### 4.1 信息溯源声明

```markdown
AI 必须声明信息来源和置信度：

- 【数据】[行业]增长率 X% → 来源：[具体报告] → 置信度：高/中/低
- 【观察】[岗位A]转[岗位B]是常见路径 → 来源：[LinkedIn/访谈] → 置信度：中
- 【推测】中小[行业]公司更看重经验而非学历 → 置信度：中（需验证）
```

#### 4.2 72 小时落地检查

每个路径必须配套：

```markdown
**路径：[目标岗位]**

72 小时内可执行的验证动作：
□ 1. 上 Boss 直聘/猎聘搜索"[目标岗位关键词]"，记录 20 个岗位的：
     - 薪资区间（中位数）
     - 硬性要求（学历/经验/证书）
     - JD 关键词高频词（30 分钟）

□ 2. 找 2 个在该岗位的人做信息访谈（通过校友/LinkedIn/脉脉）：
     - 日常工作内容是什么？
     - 转[目标岗位B]的可能性有多大？
     - 有什么坑要避免？（2-3 小时）

□ 3. 查看 5 家目标公司官网/公众号，了解：
     - 产品线和客户类型
     - 最近新闻（扩张还是收缩）
     - 团队规模（30 分钟）

□ 4. 整理自己的"[行业]+技术"经历，看能否匹配 JD 关键词：
     - [实习/项目]期间接触过什么系统？
     - 课程设计做过什么项目？
     - 能否包装成"[行业]信息化经验"？（1 小时）

**决策点**：
如果以上动作执行后你发现：
- 薪资普遍低于 8k → 重新评估是否接受
- JD 普遍要求有证书 → 将考证加入 3 个月计划
- 校友反馈转[目标岗位B]很难 → 考虑其他路径
```

#### 4.3 证伪机制设计

```markdown
**如何证明"先做[岗位A]再转[岗位B]"这个建议是错的？**

红色信号（出现任一即需重新评估）：
- 投 50 份[岗位A]简历，0 面试 → 可能是简历问题或市场饱和
- 面试 5 家都被问"为什么不直接做[岗位B]" → 路径设计有误，[岗位A]不是好跳板
- 入职后发现[岗位A]完全接触不到[岗位B]决策 → 转岗假设不成立
- 发现公司[岗位A]和[岗位B]部门有明确职级隔离 → 内部转岗通道不存在

黄色信号（需要调整策略）：
- 面试时发现自己技术栈不够 → 需补充特定技能
- 发现薪资低于生活成本 → 需考虑兼职/降低预期/换城市
```

#### 4.4 行动路线图

```markdown
**如果选择"[岗位A]→转[岗位B]"路径**

第 1 个月：
- 完成 72 小时验证动作
- 优化简历（突出[行业]+技术复合背景）
- 开始投递（目标：每周 10 份）

第 2-3 个月：
- 密集面试，收集反馈
- 同时学习[目标岗位B]方法论（看相关书籍/课程）
- 尝试做一个小作品集（分析一个[行业] App）

第 4-6 个月（入职后）：
- 主动要求参与需求评审会
- 记录客户痛点，整理成产品优化建议
- 内部寻找转岗机会

第 7-12 个月：
- 如果内部无机会，带着[岗位A]经验跳槽[岗位B]
```

## 一键启动模板

```markdown
【RAC-CAREER 求职分析模式启用】

我的背景：
- 学校：[你的学校]
- 专业：[你的专业]
- 学历：[本科/硕士/博士]
- 经验：[实习/项目经历]
- 约束：[地域/薪资/时间要求]

请严格按照以下四步执行：

**Step 1: INPUT - 输入解构**
- 识别我的隐性资产（我可能忽视的优势）
- 识别我的隐性约束（我可能忽视的限制）
- 给出竞争定位初判（正面竞争区/差异化区/风险区/禁区）

**Step 2: DIVERGE - 强制发散**
- 显性路径（obvious 选择）≤ 3 条
- 隐性路径（非 obvious 选择）≥ 4 条
- 必须包含：上下游延伸、规模下探、时间套利、风险对冲类路径
- 时间窗口评估（现在入场 vs 3 年后）

**Step 3: BATTLE - 竞争格局解剖**
对每条推荐路径：
- 竞争者画像矩阵（≥3 类竞争者）
- 准入壁垒拆解（硬性门槛+软性壁垒）
- 差异化价值主张（具体而非套话）

**Step 4: VERIFY - 验证落地**
对每条推荐路径：
- 信息溯源声明（区分【数据】【观察】【推测】）
- 72 小时落地检查（4 个具体可执行动作）
- 证伪机制设计（红色信号+黄色信号）
- 行动路线图（3/6/12 个月里程碑）

**绝对禁止**：
- 禁止只基于专业做线性推导
- 禁止不提竞争格局
- 禁止不给验证方法
- 禁止用"你很努力"作为差异化理由

确认请回复："RAC-CAREER 已加载"，然后开始四步分析。
```

## 实战检查清单

### 发散质量检查
- [ ] 隐性路径数量 > 显性路径数量
- [ ] 包含至少一条"反共识"路径（多数人不会建议的）
- [ ] 包含上下游延伸（目标岗位的上一环/下一环）
- [ ] 包含风险对冲路径（Plan B）

### 竞争分析检查
- [ ] 每类竞争者都有具体的优势和劣势分析
- [ ] 差异化理由是"人无我有"而非"你很努力"
- [ ] 硬性门槛评估真实（不夸大也不贬低）

### 验证可行性检查
- [ ] 72 小时动作是具体可执行的（有明确时间和产出）
- [ ] 证伪机制包含"什么情况说明建议错了"
- [ ] 行动路线图有 3/6/12 个月里程碑
